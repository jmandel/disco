## 2026-08-30 — build-time decisions (Slices 1–2)

16. **Budget semantics: the settlement budget measures time since the last attributed network evidence.** It is suspended entirely while attributed requests are in flight and restarts from each landed response; `maxBudgetMs` (20s) bounds hung requests. Alt: hard cap at t0+budget (contradicts G§4.2's "7s round trip → report at ~7.3s with no per-case tuning"); suspend-only-while-inflight (fires `still-active` during the Q tail right after a slow response lands). Why: only this reading satisfies both "hard-capped" (for unattributed churn — spinners, tickers) and the 7s example; attributed evidence is concrete, churn is not. Diverges: sharpens GUIDANCE §4.2; encoded in `src/settle.ts` + unit tests.

18. **Gauntlet behaviors 23–26 added** (user request): push-channel content delivery (the same notification rendered from WS push, persistent SSE, and dedicated long-poll — so "results over the standing channel" is observable, G§10), custom context menu, double-click edit, mouse-drag slider + sortable with a wire-visible drag report. 19. **SSE payloads are captured after all** via `Network.eventSourceMessageReceived` → `sse_events` table — the *body* never finishes (still flagged `streaming`), but every message is recorded. Softens DECISIONS #12.
20. **Attach-before-first-paint caveat:** the document request of a brand-new target can precede `Network.enable` (the browser process issues it before the renderer pauses), so a fresh tab's first HTML request may be absent from `requests`. `targets.observed_from`/`late` record the boundary honestly. Subsequent navigations in an instrumented tab are fully captured.
21. **Ambient DOM roots** (2026-08-30): mutation subtree roots that recur at sub-600ms cadence over ≥1.5s of *idle* observation are classified ambient; batches touching only ambient roots (and small churn) do not feed DOM quiescence. This is GUIDANCE §4.2's "always-animating subtrees" escape hatch, discovered the honest way — the gauntlet's perpetually re-rendering button held every settlement to budget. Reversible (batches still recorded, `amb` flag on the event). Large batches (>12 adds+removes) always count as real.
22. **Unread fetch bodies stall `loadingFinished`** (2026-08-30): a fire-and-forget `fetch()` whose response body the page never reads gets `responseReceived` but no `loadingFinished` — the request pends indefinitely and (under DECISIONS #16) suspends the settlement budget. Found by the gauntlet's `POST /api/drag-report`. Fix: after headers + `unreadBodyGraceMs` (1.2s) of body silence, the request is demoted (`body_state='unread'`, a `stalled` response event releases settlement); `Network.dataReceived` re-arms the timer, and a late `loadingFinished` completes normally. The gauntlet keeps the unread POST as the regression case.
23. **Self-feedback suppression** (2026-08-30): a pointer action on a small element (≤ `selfFeedbackMaxArea` px²) whose only visual changes fall inside the target's own inflated box does not count as visual activity — pressed/focus repaints are affordance feedback, not effects, and were turning no-op clicks into `settled:visual`. Large targets (canvases, panels) keep in-element pixel signals; DOM/network channels are never suppressed.
24. **Error sentinel fires on any non-ambient 4xx/5xx** (2026-08-30), attributed or not — the gauntlet's optimistic-save case delivers its 500 *after* settlement closes (a delayed async status check), which is precisely the between-action failure the sentinel exists for. G§5.3's "on attributed requests" was written before this case; scoping to non-ambient keeps heartbeat noise out.

35. **`until` — the postcondition on `act()` (2026-08-30).** `act()` is a *quiescence* primitive and was never a readiness guarantee: a >Q gap between the last response and the render (a debounce, a timer, an unattributed second hop) closes settlement while the screen still says "loading…". Gauntlet scenario 27 (`renderDelayMs`) is the deterministic form; live, saucedemo's `performance_glitch_user` login click settles **`no-effect` at 500ms** and the pack survived only because the glitch freezes the main thread so its next `evaluate` stalled on CDP until the route had changed. `expect` is client-side and never waits (§1.4). So readiness must be a **predicate**, and it must live in the **daemon**: only the daemon can keep the causality window open until the predicate holds — a client-side act+watch composition loses attribution of anything past the 1.5s `trailing` grace. Shape: `act({ until: { selector | fn (+fnArg) | urlLike, budgetMs=5000, tailMs=1000 } })` → `report.until = { matched, elapsedMs, preview?/request?, diagnosis? }`. The two signals stay **independent** — verdict = what the page did, `until` = whether the state arrived — and the return is gated on both, bounded: predicate first → `Settler.cap(tailMs)` (matched + `still-active` is a pass; the verdict says what still moves); settlement first → the window stays open, the predicate is watched to its budget, and on a match a short seeded tail settle lets the announced response (`urlLike` fires on request START) and its render land in the report. With `until` the window closes when the postcondition decides (no background settler): the script moves on. Discovery omits it; automation always passes it. `watch()` and `until` share one loop (`runWatch`), which now takes `fnArg` (friction #4) and re-fetches the frame per check. Tests: `test/gauntlet/until.test.ts`.
36. **Window ownership + one signal mapper (2026-08-30, review).** `backgroundSettle` (F3) kept running after `awaitSettlement` re-armed the *same* action — the window was reused, not replaced, so bg's "superseded" check never fired — and could `closeWindow` under it at bg's own 3s budget, stranding later requests as `trailing`/`none`. Now the window records its bg canceller (`ActionWindow.bg`); `awaitSettlement` takes over by cancelling it, and bg refuses to close a window it no longer owns. All settlers (main / background / until-tail) feed through one `signalFromEvent` — bg used to miss nav/dialog/new-target/download and self-feedback suppression lived only on the main path.

The RPC framer decodes UTF-8 as a stream (a multi-byte character split across socket chunks became U+FFFD); `framer` is exported and unit-tested. Watch / scroll-absorb / until tunables moved into `defaults.ts`.
38. **Layer 1 speaks one language and has one wait (2026-08-30, review §3/§5).** `lib/nav.ts` was two selector languages (`assertVisible` raw `querySelector`, `actIfPresent` Playwright) and one shape re-implemented five times across packs (`Date.now()` + `sleep(300)` loops). Now: `until(s, pred, {budgetMs, frame, msg})` — the Layer-1 postcondition move, throws with the diagnosis — and `reached(report)` — gates on `report.until`/`diagnosis` with a message that carries verdict + diagnosis; `assertVisible` = `until({selector, visible: true})` in Playwright syntax with a 2s budget; `waitForFrame` = `until` with `frame:`. Predicates grew `visible` (laid out with a box) and `landed` (the response is back — status known — and the body's fate is decided: captured, or known-uncapturable such as an `unread` fire-and-forget fetch after its 1.2s grace, never still `pending`; for `act({until})` the request must have STARTED after dispatch — a previous action's late tail can't satisfy this one; for `watch()` it must have responded since watching began), and `until.frame` names a postcondition that lives in a different frame than the action (OpenEMR: finder-row click → chart frame). A missing frame is a `frame-not-found` diagnosis with a frame census from `act()`, and a waited-for condition in `watch()` (the frame is re-resolved per check), instead of an RPC throw. `fill` kind (select-all + type, `""` clears) replaces the packs' `evaluate()` value hacks — real key events through the choke point, so controlled inputs and attribution both see a normal edit. `KINDS` (src/kinds.ts) is the one table behind `ActParams.kind`, the CLI and the client sugar. Report `otherActivity`/`console`/`dialogs` are tree-scoped like sentinels. `run-check` reads `target = {url, scope}` from each pack's `check.ts` (adding a pack touches no Layer-1 file); `apps/gauntlet/check.ts` added. Packs refactored: zero `sleep(` in `apps/` and `lib/`; saucedemo `login` waits for *either* the inventory or the app's error banner (the glitch user's `no-effect` click is now safe by construction); OpenEMR's five loops are `until` calls; gauntlet scripts carry their postcondition on the click.
39. **Responsiveness is a tested contract (2026-08-30).** "We tried to make it fast and it didn't crash" is not a claim. 43. **The four OPEN items from the fresh-eyes runs, decided with Josh (2026-08-31).** (1) **`until` combinators, one level:** `{ any: [pred, …] }` holds when one arm holds and `report.until.which` names it (the arm's `name`, else its index); `{ all: [pred, …] }` needs every arm — arms are full predicates, so a wire-AND-DOM postcondition is `all: [{ urlLike, landed: true }, { selector }]`; `firstOf` stays for after-the-fact checks. (2) **URL-substring rules** instead of query-key-aware families: a per-app `rules` table (`ambient` | `not-ambient` | `mute-sentinel`; persists across runs) matched against the FULL url at attribution time — one rule covers a host (`backtrace.io`) or a query key (`Location?_tag=Login`), `not-ambient` beats a mis-learned family, ambient rules take requests out of attribution *and* settlement; `families --ambient|--not-ambient <url-part>`, `session new --ignore <url-part>`, `s.ignore()`/`s.attend()`, `disco rules`, `families --forget` (learned state cleared, rules kept), `families.last_run` for stale families. Families keep their path-shape identity — the alternative changed identity everywhere for a case a rule handles. (3) **Closure capture fails fast at runtime, no static lint:** a ReferenceError inside `until.fn`/`watch.fn` ends the wait immediately with `diagnosis.error` carrying the hint (page functions capture nothing; pass it as `fnArg`/`args`), `evaluateAfter` reports it, `evaluate` rethrows it — zero false positives, which a regex lint could not promise. (4) **Per-app sentinel mutes** on the same rules table: `disco sentinels --mute <name> [--selector] [--text] [--url]` (`s.mute()`); muted firings are still recorded (`sentinels.muted=1`, `detail.mutedBy`) — never hidden from the store — but take no screenshot and are not reported or streamed. Still OPEN: query-key-aware family identity (only if rules prove insufficient); `until` nesting deeper than one level.
