## 2026-08-30 — v0.1 → v0.2 revision (pre-build, per REVIEW.md; human-approved)

1. **Adopt REVIEW.md into the docs before building.** Alt: build to v0.1 and log divergences. Why: the review found feasibility gaps (screencast rate vs Q, attribution mechanism, FTS content model, attach-mode scoping) that would have forced divergences in Slice 1–2 anyway; cheaper to fix the constitution first. Human chose this option. Diverges: supersedes v0.1 text throughout; each item below.
2. **Screencast at native rate is the visual signal; 3 fps is a persistence cap.** Alt: throttled screencast + pixel diff; `captureScreenshot` polling. Why: REVIEW A2 — a 3 fps stream cannot resolve a 300 ms quiet window, and canvas regions have no other signal. Diverges: GUIDANCE §3.4/§4.2, BRIEF §1.7 (rewritten).
3. **Attribution tiers are `task` > `window` > `dependency`, with `ambient` as an explicit tag.** `task` is detected in-page (one-shot capture-phase listener at dispatch marks the event's task + microtask checkpoint), not via CDP initiator stacks. Alt: `Debugger.setAsyncCallStackDepth`. Why: REVIEW A1 — sync initiator stacks are blind to framework schedulers; async stacks cost renderer perf and still lose across `MessageChannel`. Diverges: GUIDANCE §4.4 (rewritten).
4. **Gauntlet ambient traffic is OFF by default; classifier warm-up is explicit.** Why: REVIEW A3 — a long-poll reissuing inside a window holds settlement to budget until its family is learned; Slice 2's timing suite must be deterministic (BRIEF §6.5). Diverges: BRIEF §3, §1.13, §1.14 (rewritten).
5. **Attach mode requires a target scope.** Why: REVIEW A7 — privacy; a human's browser has other tabs. Diverges: GUIDANCE §3.2, BRIEF §1.15 (added).
6. **Instrumentation order fixed (`waitForDebuggerOnStart`, isolated world `disco`).** Why: REVIEW A6. Diverges: GUIDANCE §3.4, BRIEF §1.16 (added).
7. **FTS content model: textual bodies also stored in SQLite (`bodies.text`), blobs for everything.** Alt: contentless FTS over blob-only bodies. Why: REVIEW A9 — "external-content FTS" needs the text in a table; keeping it there also makes `appearances()` and one-line SQL trivial; storage duplication for text bodies is accepted. Diverges: BRIEF §1.5, GUIDANCE §6.2 (rewritten).
8. **Drop daemon-side `extract`; add in-page `evaluateAfter`.** Alt: keep temp-module dynamic import. Why: REVIEW B — the unit of context cost is the agent turn; one turn is one Bun script that can already read the store after `act()`. Deletes the closure-transfer footgun. Diverges: GUIDANCE §2.5/§4.1/§4.3, BRIEF §1.4, Slice 5 (rewritten).

## 2026-08-30 — build-time decisions (Slices 1–2)

16. **Budget semantics: the settlement budget measures time since the last attributed network evidence.** It is suspended entirely while attributed requests are in flight and restarts from each landed response; `maxBudgetMs` (20s) bounds hung requests. Alt: hard cap at t0+budget (contradicts G§4.2's "7s round trip → report at ~7.3s with no per-case tuning"); suspend-only-while-inflight (fires `still-active` during the Q tail right after a slow response lands). Why: only this reading satisfies both "hard-capped" (for unattributed churn — spinners, tickers) and the 7s example; attributed evidence is concrete, churn is not. Diverges: sharpens GUIDANCE §4.2; encoded in `src/settle.ts` + unit tests.
17. **Input kinds in v1: click, rightclick (contextmenu), dblclick, middleclick, hover, drag (mouse-based), wheel/scroll, press (incl. modifier combos), type, select, navigate.** Added per user request 2026-08-30. Mouse-based drag = down → stepped real-time moves → up; covers sliders/sortables/resizes. `OPEN`: native HTML5 draggable/dragstart DnD needs `Input.setInterceptDrags` + `Input.dispatchDragEvent` — deferred until a real app needs it.
18. **Gauntlet behaviors 23–26 added** (user request): push-channel content delivery (the same notification rendered from WS push, persistent SSE, and dedicated long-poll — so "results over the standing channel" is observable, G§10), custom context menu, double-click edit, mouse-drag slider + sortable with a wire-visible drag report. Slice 2/3 acceptance extended accordingly.
19. **SSE payloads are captured after all** via `Network.eventSourceMessageReceived` → `sse_events` table — the *body* never finishes (still flagged `streaming`), but every message is recorded. Softens DECISIONS #12.
20. **Attach-before-first-paint caveat:** the document request of a brand-new target can precede `Network.enable` (the browser process issues it before the renderer pauses), so a fresh tab's first HTML request may be absent from `requests`. `targets.observed_from`/`late` record the boundary honestly. Subsequent navigations in an instrumented tab are fully captured.
21. **Ambient DOM roots** (2026-08-30): mutation subtree roots that recur at sub-600ms cadence over ≥1.5s of *idle* observation are classified ambient; batches touching only ambient roots (and small churn) do not feed DOM quiescence. This is GUIDANCE §4.2's "always-animating subtrees" escape hatch, discovered the honest way — the gauntlet's perpetually re-rendering button held every settlement to budget. Reversible (batches still recorded, `amb` flag on the event). Large batches (>12 adds+removes) always count as real.
22. **Unread fetch bodies stall `loadingFinished`** (2026-08-30): a fire-and-forget `fetch()` whose response body the page never reads gets `responseReceived` but no `loadingFinished` — the request pends indefinitely and (under DECISIONS #16) suspends the settlement budget. Found by the gauntlet's `POST /api/drag-report`. Fix: after headers + `unreadBodyGraceMs` (1.2s) of body silence, the request is demoted (`body_state='unread'`, a `stalled` response event releases settlement); `Network.dataReceived` re-arms the timer, and a late `loadingFinished` completes normally. The gauntlet keeps the unread POST as the regression case.
23. **Self-feedback suppression** (2026-08-30): a pointer action on a small element (≤ `selfFeedbackMaxArea` px²) whose only visual changes fall inside the target's own inflated box does not count as visual activity — pressed/focus repaints are affordance feedback, not effects, and were turning no-op clicks into `settled:visual`. Large targets (canvases, panels) keep in-element pixel signals; DOM/network channels are never suppressed.
