# DECISIONS — disco v4

One line each. Adding an option, predicate, command, file or concept requires deleting one and a line here.
`test/budget.test.ts` enforces the counts. Every later feature request is answered first with "which primitive's OUTPUT changes?".

## Shape (2026-09-01)

- **v4 from v2.** Engine kept (CDP attach, no page instrumentation, always-on SQLite recorder). API, predicate DSL and 5-file pack replaced. Why: every stranger round added a predicate nuance; the agent should write Playwright and the report should carry the evidence.
- **Three verbs**: `look`, `act`, `sql` (+ `body`, `json`), plus `waitFor` and `reached`. Nothing wraps what Playwright or SQL already do.
- **`act` is a bracket around the agent's code.** One budget, `max`: the default timeout of every Playwright call inside `run` and `until`, and the longest the act observes. A failing click is diagnosed within max; probe with a small max.
- **Bare acts return on quiet**: no request/response/frame/console/dialog/nav, no DOM change, no request this act started still unanswered; third-party sites (telemetry) count for none of it. `returned` and `pending` say what happened. No verdict.
- **The report proposes untils**: responses with their `+ms`, roles that appeared with their new state (`selected`, `expanded`, `checked`), the one that left (only if it was unique), the url path, a storage key, page text (collected through shadow roots; never a fragment already on screen; an `<option>` as `attached`). Each was false before the action, and each DOM/url/storage proposal must hold 400 ms after it or it is not printed.
- **`alreadyTrue` is generic**: any until that resolved before dispatch. A navigation's until is the `nav` event. The refusal says the action ran, and a note describes the target's state now; a failed response wait lists what answered in the 5 s before the act.
- **Diagnoses** parse the locator out of Playwright's message and hit-test it: not-found (with pasteable candidates), hidden, disabled, occluded (a styled control is named as such, not "dismiss the dialog"), offscreen, unclickable, detached, timeout, error (Node-vs-page hint). A click that landed but blocked past max counts, with a note.
- **`look`** renders numbered marks in a scratch page of ours (never in the app's page), full page up to 4000 px, document coordinates; names controls as the accessibility tree does (aria-hidden skipped, label over placeholder, weak names re-read from Playwright's aria view); durable selector = data-test, stable id, unique `role=[name]` (exact, else an anchored whitespace-tolerant regex), else a css path; lists anchors without href, tabindex/onclick/draggable targets, walks open shadow roots; marks off-canvas (left of, above, right of the page — never below the fold) and unnamed dialogs.
- **`open`** navigates as its own act and returns when the page is quiet; prefers the page it drove before (remembered CDP target id), then the url, then a page no popup opened; writes `apps/.current`, which `close` keeps because the log outlives the browser.
- **One recorder per browser**, claimed in browser.json; later sessions are silent and stamp their windows; a silent session takes over when the recorder is gone. A request still unanswered when its recording session closes is marked `error`, never left `pending`.
- **Storage** snapshots use `context.cookies()` (HttpOnly visible) plus localStorage and sessionStorage. **Downloads** come from CDP `Page.downloadWillBegin`. Screenshots are `<hash>.jpg`; `shots` carries the page url.
- **`json`** prefers a path-boundary match, waits 1 s for a body (or a matching request) still in flight, and **throws** when nothing matched (naming what did) or when a query-string fragment spans several endpoints — a fact you could not find is never `null`.
- **`sql --json`** has one shape: an array of rows with JSON text cells parsed. `sql` errors name the table's columns. `until.value` keeps JSON (≤ 2 KB) and describes Playwright objects.
- **Pack = `README.md` + `sdk.ts`** (+ gitignored `store/`, + `evidence/`). `sdk.ts` exports workflows and `check(s)` and runs its own check under `import.meta.main`, leaving the browser up (warm first, cold after `disco close`). Every `close` copies each act the README cites into `evidence/` — report, diagnosis shot, and wire (requests with headers, write bodies, navigations) — and names cites with nothing behind them (judge C: every unbacked claim was a fact that lived only in the store). A number without an act id is a guess.
- **`stats` is `scripts/stats.ts`**, dev-side, outside the five commands; `_record` is an internal subcommand spawned by `open`. **No `withApp`**: a script closes in `finally`.

## Rejected, and why

Server knobs leaking across sessions and the WS banner in every diff (the app's; the warm-from-messy rule catches the first); long-poll attribution by start time (documented); folding diff lines that only change a number, a user-identity reminder, a read the app performs with POST under `writes`, a redirect the app fires 3 s after quiet (all verdicts — the log has the facts); mouse-only targets without a role in `look` (no handler is detectable without instrumentation; `look(selector)` covers them); copying untils across acts and guessed column names (the report and the error already say so); a "wait for all bodies of this act" helper and a `disco evidence` command (`json` waits, `close` copies).
- **Opus round fold-back (gauntlet 19 min / 32 checks; openmrs read-only 15 min / 4 checks; expired budgets 48–50 s):** `json` prefers the collection (`/visit?…`) over an item (`/visit/<uuid>`) when both answered; `until.value` prints on the until line; page-text proposals are their own kind and say they hold only until the text changes; a `not-found` on `:has-text()`/`text=` names the control whose accessible name carries that text. A navigating act also proposes the `nav`-event until (the one that is false beforehand even when the page was already there); an "appeared" proposal must be on-canvas, not merely Playwright-visible (Opus saucedemo: a drawer parked at x = −276 for 100 ms after mount). Rejected: raw `page.mouse` coordinates on an unscrolled element (Playwright's, not disco's; use `dragTo`/`scrollIntoViewIfNeeded`); `stats` calling a run "unclean" when its check asserts failures on purpose (the check's own PASS/FAIL is the verdict).
- **Opus judge fold-back:** `close` also checks each cited claim — a number quoted beside `act:N` must appear in that act's evidence — and counts sentences whose numbers carry no cite. Why: every cited-only and most bare items across three Opus packs were numbers the cited report did not contain, or `sql` aggregates with no act behind them.
- **Read-write pair (Fable 23 min / 7 checks / 6 s expired; Opus pending) fold-back:** `json` throws when the newest match answered ≥ 400 (an error body handed back as a record surfaced two steps later); `look`'s text folds a table's repeated controls after two of each role+name; the claim lint ignores inline code; close says how many cites were already present. `role=[name=…]` verified exact and case-sensitive (a stranger believed it was a substring) — one README sentence says so.
- **Opus read-write (25 min / 8 checks incl. 6 writes; one cold run met a server 502 and cascaded at 20 s per step):** the README template's check stops at the first failed step, and the pack section names the progress query. Rejected: making `look` citable as an act (a look is not an action; cite the act around it), and de-duplicating app chrome across looks (state).
- **README A/B for Opus (control d694c30 vs treatment 3cc7309, three apps each):** treatment packs had 42 checks vs 30, 1 already-true refusal vs 4, expired budget per act about equal. Fold-back from the six logs: the claim lint keeps `act:N` written in backticks and ignores §-numbers and list markers; `close` waits up to 1 s for responses still in flight; `look` lists test-id elements that show text as `value` rows (the app's selector vocabulary); the CLI hints when statements return nothing; README: `json` is async and throws on 4xx/5xx, `ui` is a start-vs-end diff, `run` column, `sql` scoping, the gauntlet binds two ports, the stats rule counts failed untils only. Rejected: a CLI verb to call one pack workflow (a script is one line).
- **A/B judges (control 85/90/84 % backed, treatment 89/95/91 %; unseen tasks from the pack in both arms, faster in treatment):** the wire evidence now carries read bodies too (writes always; reads while the act stays under 512 KB), `act:N-M` ranges expand, and `close` counts sentences with neither a cite nor an sdk function (printed, not judged — narrative is allowed, a fact there is a guess); the README states the claim-check rules in one sentence. Still open, asked by three judges: recording `look` as a citable act — a look is not an action; Josh's call.
- **Instead of citable looks (asked by three judges):** every act keeps the accessibility tree it left behind (a content-addressed blob named in `report.aria`) and cited acts carry it as `act-N-aria.txt`, so a screen fact cites the act that produced the screen; the README's pack example exports `anchors` and asks that screen facts be exported constants referred to by name (the lint counts an sdk export name as backing). A look stays a view, not an action. Why: what a look shows *is* the post-state of the last act; recording it there costs a few KB per act, deduplicates, and adds no concept.
- The claim lint keeps single-token inline code (`whoAmI()`, `anchors.chart`) visible, so an sdk name in backticks backs its sentence (rec-round openmrs #1). README: a body from the CLI is one `sql` line.
- A script's `close` prints the same evidence/claim summary as `disco close` (to stderr); a cited range is capped at 10 acts with a warning (a 88-act range copied 1.1 MB); the `value:` line clips at 1200 chars. (rec-round saucedemo #1–3)
